# existing-project-refactoring

从现有代码和真实行为出发，识别架构耦合和模块边界问题，制定可验证、可回滚的分阶段重构计划，在保持功能稳定的同时改善可维护性和扩展性。

## 适用场景

- 已有项目结构混乱或模块职责不清。
- 页面、业务逻辑、数据访问和外部 SDK 相互耦合。
- 需要拆分大文件，但不能一次性推翻现有实现。
- 需要替换数据库、网络服务或第三方 SDK。
- 需要在保持现有行为的前提下进行架构迁移。

该 Skill 面向支持 Agent Skills 格式的智能体，不依赖特定 Agent、MCP 服务或编程语言。

## 使用方式

### 安装

将仓库目录复制到所用 Agent 的 Skills 目录，并保留目录名称：

    existing-project-refactoring/
    └── SKILL.md

目录名称和 SKILL.md 中的 name 字段必须保持一致。

### 调用

支持显式调用的 Agent 可以使用：

    $existing-project-refactoring

也可以直接描述已有代码库，并要求先分析现状和制定重构计划，再修改代码。

## 工作流程

1. 读取项目规则、README、配置、设计文档和当前 Git 状态。
2. 梳理入口、模块、数据流、外部依赖、构建和运行表面。
3. 跟踪一个真实用户行为，确认状态、持久化、集成和错误恢复路径。
4. 区分领域规则、应用编排、接口适配器、框架代码和可重建缓存。
5. 记录必须保持不变的行为，包括数据结构、顺序、错误处理和降级路径。
6. 找到能够降低耦合的最小迁移边界。
7. 制定每个阶段都可以独立验证和回滚的迁移计划。
8. 编写覆盖正常路径、边界场景、失败处理、数据兼容性和并发行为的回归矩阵。
9. 在方案获得批准前停止修改实现代码。

## 输出内容

- 当前结构和数据流
- 必须保持的现有行为
- 耦合点和根因
- 目标架构
- 迁移边界和模块接口
- 分阶段重构计划
- 回归矩阵
- 回滚和失败处理
- 风险、假设和待决策项

## 目录

| 路径 | 内容 |
|---|---|
| SKILL.md | 核心工作流 |
| references/ | 现状分析、迁移和风险控制参考 |
| templates/ | 现状审计、重构计划和回归矩阵 |
| examples/ | 示例请求 |
| tests/ | YingTu 真实场景验证记录 |
| scripts/validate_skill.py | 本地结构验证脚本 |

## 本地验证

在仓库根目录运行：

    python scripts/validate_skill.py

该仓库还配置了 GitHub Actions，会在 Push 和 Pull Request 时自动执行验证。

## 边界

该 Skill 负责现状分析、目标架构和迁移计划，不会默认直接修改代码。新项目的初始架构设计请使用 [new-project-architecture](https://github.com/Jaxanyn/new-project-architecture)。\n
