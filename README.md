# existing-project-refactoring

面向通用 AI Agent 的存量项目重构 Skill。它先从代码和真实行为中建立证据，再识别耦合、划分迁移边界并制定可验证、可回滚的分阶段方案，在保持功能稳定的同时改善可维护性和扩展性。

## 解决什么问题

存量项目不能只按理想架构重新设计。直接大范围改写容易丢失隐含行为、破坏兼容性，或让问题从一个模块转移到另一个模块。

这个 Skill 采用一条证据优先的重构流程：现状扫描 → 真实行为追踪 → 耦合与根因分析 → 目标边界设计 → 分阶段迁移 → 回归与回滚验证。它帮助 Agent 在每次修改前明确保留什么、先切哪里以及如何证明没有引入回归。

## 适用场景

- 项目结构混乱、模块职责不清或依赖方向失控。
- 页面、业务逻辑、数据访问和外部 SDK 相互耦合。
- 需要拆分大文件，但不能一次性推翻现有实现。
- 需要替换数据库、网络服务或第三方 SDK。
- 需要在保持现有行为的前提下迁移架构。
- 需要把重构拆成多个可独立审查和回滚的阶段。

该 Skill 遵循通用 Agent Skills 格式，不依赖特定 Agent、MCP 服务、编程语言或框架。

## 快速开始

### 安装

将仓库目录复制到目标 Agent 支持的 Skills 目录，并保留 SKILL.md：

~~~text
existing-project-refactoring/
└── SKILL.md
~~~

目录名称和 SKILL.md 的 name 字段应保持一致。不同 Agent 的发现路径请参阅其官方文档；本仓库提供的内容是纯 Markdown、模板和验证脚本。

### 调用

支持显式 Skill 调用的 Agent 可以使用：

~~~text
$existing-project-refactoring
~~~

也可以使用自然语言：

~~~text
使用 existing-project-refactoring。请先分析当前代码和真实行为，
列出必须保持的兼容性，再给出分阶段重构计划。在我确认前不要修改实现代码。
~~~

## 工作方式

1. 读取项目规则、README、配置、设计文档和当前 Git 状态。
2. 梳理入口、模块、数据流、外部依赖、构建和运行表面。
3. 跟踪一个真实用户行为，确认状态、持久化、集成和错误恢复路径。
4. 区分领域规则、应用编排、接口适配器、框架代码和可重建缓存。
5. 记录必须保持不变的行为，包括数据结构、顺序、错误处理和降级路径。
6. 找到能够降低耦合的最小迁移边界。
7. 制定每个阶段都可以独立验证和回滚的迁移计划。
8. 编写覆盖正常路径、边界场景、失败处理、数据兼容性和并发行为的回归矩阵。
9. 输出验证命令、停止条件和待决策项，在方案确认前停止修改实现代码。

## 典型输出

- 当前结构、入口和数据流。
- 必须保持的现有行为和兼容性约束。
- 有证据支撑的耦合点、根因和风险。
- 目标架构、模块接口和迁移边界。
- 分阶段重构计划，以及每阶段的验证和回滚点。
- 覆盖正常、边界、失败、兼容性和并发场景的回归矩阵。
- 风险、假设、待决策项和剩余影响。

## 示例请求

~~~text
使用 existing-project-refactoring 重构订单模块。
先扫描当前入口、数据流、外部依赖和测试，跟踪创建订单这条真实流程，
列出必须保持的行为与兼容性约束，再提出最小迁移边界。
请把重构拆成每步可验证、可回滚的阶段，并在方案确认前不要改代码。
~~~

## 仓库内容

| 路径 | 内容 |
|---|---|
| SKILL.md | 核心触发条件和重构工作流 |
| references/ | 现状分析、迁移和风险控制参考 |
| templates/ | 现状审计、重构计划和回归矩阵模板 |
| examples/ | 可直接改写的示例请求 |
| tests/ | YingTu 真实场景验证记录 |
| scripts/validate_skill.py | 本地结构验证脚本 |

## 本地验证

在仓库根目录运行：

~~~bash
python scripts/validate_skill.py
~~~

还可以运行通用 Skill 格式检查：

~~~bash
python <skill-creator>/scripts/quick_validate.py .
~~~

GitHub Actions 会在 Push 和 Pull Request 时自动执行仓库验证。

## 边界

该 Skill 负责现状分析、目标架构和迁移计划，不默认直接修改代码。新项目的初始架构设计请使用 [new-project-architecture](https://github.com/Jaxanyn/new-project-architecture)。
